# フィジカル投扇興

江戸時代の座敷遊び「投扇興（とうせんきょう）」を物理演算で再現した、スマホブラウザ向け 3D ゲーム。
開いた扇をふわりと投じ、枕（台）の上の蝶（的）を落とし、扇・蝶・枕が結ぶかたち（銘）で
得点を競います。銘には源氏物語五十四帖の名が使われています。

**Play**: https://sin1.studio/tosenkyo/ / [sin1's studio](https://sin1.studio)

## 遊び方

1. **狙う** — 蝶に寄った視点。狙いたい場所に触れるとレティクルが移り、指を引いて微調整（狙いは呼吸でわずかに揺れる）
2. **投じる** — 俯瞰視点に切り替わり、下から上へスワイプ。速さと距離が強さに、左右のずれが方向になる。
   **スワイプの形が扇の飛び方になる**：直線＝無回転で水平を長く維持／弧＝ヨー回転／円＝ロール／ジグザグ＝ピッチ
3. **銘定** — 物理演算で扇・蝶・枕が落ち着いたかたちを判定し、銘と点が付く（説明は銘定表と共通）
4. **五投**の合計で番付（手習の身〜扇聖）が決まる
5. **伝える** — 結果画面の「結果を伝える」で、五投のうち最高の銘が実際に決まった形のまま大きく表示される。スクリーンショットを添えてポストできる（30点以上の銘は投擲直後の札からも開ける）

コツ：蝶の下端を掬うと良い銘が出やすい。枕の上端は「コツリ」、強すぎれば「野分」（過料）。

## 銘定について

本作の銘定は、都御流の源氏物語形式を基に、御扇流・其扇流など諸流派の定めを参考にした
独自のものです（銘と点は流派ごとに異なります）。ゲーム内「銘定表」に一覧があります。
銘定表の行をタップすると、その銘の形を実際の座敷で3D表示します（見本の配置は `main.js` の `MEI_POSE`、縮小図は `mei/*.jpg`）。
銘定表には銘ごとの「コツ」と「出現率（参考値）」も載せています（`MEI_TIP`）。

判定は、扇・蝶・枕が止まった時点で**実際に触れ合っているか**で決めます（`touchNow()` → `judge()`）。
例：夢浮橋＝扇が床に触れず、枕と蝶だけに支えられている／紅梅＝蝶は枕の上に立ったまま、扇が床に触れず枕の上に乗る。

### 出現率の検証（2026-11-14）

`?debug` の `dbgSim(power, aimX, aimY, azimuth, form, g)` は、描画せずに一投を最後まで計算して銘を返します
（本番と同じ `stepPhysics` / `judge`）。これで狙い・強さ・払い方をばらばらにした10万投と、
強さ×狙いの格子約2万投を試し、銘定表の数字を出しています。主な値：

| 銘 | ばらばら | コツ通り |
|---|---|---|
| 夢浮橋 | 0.4% | 2.5% |
| 桐壺 | 0.04% | 1.3% |
| 澪標 | 0.4% | 6% |
| 浮舟 | 0.02% | 0.3% |
| 紅梅 | 0.35% | 5% |
| 花宴 | 0.09% | 0.5% |

スワイプの強さは `POWER`（中心0.6・幅0.75倍）で真ん中寄りに縮めてから投げの強さにしています（ちょうど良い強さを出しやすくする調整）。

物理は固定刻み（`CFG.fixedDt`）で進め、余りを次のフレームへ持ち越して描画は補間するので、
端末の描画速度（20〜144fps で確認）によらず同じ入力なら同じ結果になります。
`dbgJudgePose(id)` で、銘の見本の配置がその銘として判定されるかを確かめられます。

## 技術構成

- **Three.js** (r160) — 描画。CDN (jsdelivr) から ES Modules で読み込み
- **cannon-es** — 物理演算。扇には抗力・揚力・姿勢復元・フラッタを独自に付加
- ビルド不要の静的サイト。`index.html` / `style.css` / `main.js` の 3 ファイル構成
- 効果音は WebAudio でリアルタイム合成（音源ファイルなし）
- ベストスコア・言語設定は localStorage 保存
- UI は日英切替対応（タイトル画面右上のボタン）。漢字（タイトル・銘）はそのまま、フリガナはローマ字に、説明系は英語になる。英語モードの短冊は横組み
- OGP 画像 `ogp.png` 同梱（og:image / og:url は公開 URL の絶対パス）

### ローカル実行

```bash
python -m http.server 8642
# → http://localhost:8642
```

※ ES Modules を使うため file:// では動きません。
※ アセット更新時は index.html 内の `?v=N` を上げるとキャッシュが確実に更新されます。

### デバッグモード

`?debug` を付けると `window.dbgThrow(power, aimX, aimY)` などが使え、
判定結果が console に出ます。`window.CFG` / `window.AERO` を書き換えてのライブ調整も可能。
`?debug&wire` で物理形状をワイヤー表示、`dbgShareMei(id)` で任意の銘の「伝える画面」を表示。

## 月間番付

結果画面の「番付に載せる」で、五投の合計点を月間番付（毎月リセット、JST）に載せられます。
記録の受け皿は GAS Webアプリ＋スプレッドシート（`gas/Code.js`、`main.js` の `RANK_URL`）。

- 送るもの：名前（12字まで）・五投の銘・**各投げの入力**（強さ・狙いの位置・左右・払い方の形）・物理の版 `PHYS_VER`
- 合計点はサーバー側で銘から計算し直します。
- 同じ入力なら必ず同じ結果になるので、番付を開くと閲覧者のブラウザが上位の五投を `simThrow()` で計算し直し、
  一致すれば「✓ 再生で確認」、違えば「⚠ 再生と不一致」を付けます。物理・判定を変えたら `PHYS_VER` を上げてください（旧版の記録は確かめません）。
- 「再生」でその五投を実際の座敷で見られます（再生中は点数・最高記録に影響しません）。
- Chrome と Safari（描画エンジンが違う）で計算が完全に一致するかは未確認です。

GAS の再デプロイは `clasp push -f` → `clasp redeploy <deploymentId>`（URL を変えないため）。
新規作成直後は、エディタで `setup` を一度実行して権限を承認しないと `/exec` が使えません。

## 3D モデル

扇・枕・蝶は TripoAI で生成した GLB（`models/`）。物理 body の原点・軸に合わせて焼き込み済みで、
`main.js` の `withModel()` が読み込みます。読み込み前・失敗時は従来のコード生成形状
（`buildFanMesh` など）を表示します。GLB を差し替えたら `MODEL_VER` を上げてください。

**モデル・画像の利用について**：`models/` の 3D モデルと `mei/`・`img/`・`ogp.png` の画像は
本ゲームのための素材です。単体での再配布、AI・機械学習の学習データとしての利用はご遠慮ください。

## 広告

- 結果画面の「ゆかりの品」は Amazon アソシエイトのリンク（内容に合わせて手で選んだ3件）。
  うっかり押しを避けるため、結果画面の項目は上から順に表示し、関連商品は最後に間を置いて出します。
- `index.html` の `<div id="ad-slot">`（結果画面下部）に AdSense 等のコードを
  挿入すると表示されます。空の間は畳まれて非表示です。

## 調整パラメータ

- `CFG`（main.js 冒頭）— 投擲速度レンジ、弾道（launchUpBias）、投数など
- `AERO` — 扇の空力（抗力・揚力・浮遊感・姿勢復元）、`kSpent`（当たった後に扇の勢いが尽きる速さ）
- 銘定は `MEI` と `judge()` に集約
